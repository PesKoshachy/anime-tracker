# Anime tracker

Аниме-доска на GitHub Pages: тайтлы, прогресс, приоритеты, AniList и колесо выбора.

## Облачное сохранение

Supabase проект `uwpdtnppplweacxjxkar`. В `cloud.js` используется только публичный publishable key. Таблица `anime_collections` защищена RLS: читать и изменять запись может только её владелец из Supabase Auth. Анонимному клиенту доступ не предоставляется.

На сайте нажмите «Аккаунт и сохранение», укажите почту и откройте ссылку из письма на том же устройстве. На первом входе, если облачная коллекция отсутствует, локальные тайтлы автоматически переносятся. Если коллекция уже существует, загружается облачная версия; кнопка «Добавить локальные тайтлы» импортирует только отсутствующие ID. Совпадающие тайтлы не заменяются.

Коллекция и настройки колеса сохраняются одним снимком. Изменения отправляются автоматически; локальная очередь разделена по ID аккаунта. При потере сети очередь повторяет отправку и сохраняется между открытиями страницы. Проверка ревизии не позволяет незаметно заменить более свежую версию с другого устройства. При конфликте пользователь выбирает версию; резервная копия заменяемой коллекции остаётся в локальном хранилище. Кнопка «Скачать копию» экспортирует текущий снимок JSON.

Исходная локальная коллекция хранится отдельно и возвращается после выхода. Не очищайте данные браузера, пока статус не показывает «Сохранено в облаке».

## Supabase

Схема создания базы: `cloud-schema.sql` (выполнена для текущего проекта). Повторно выполнять CREATE на существующем проекте не нужно.

Authentication → URL Configuration → Site URL: `https://peskoshachy.github.io/anime-tracker/`.

Встроенная почтовая отправка Supabase ограничена адресами участников организации и лимитами сервиса. Для личного входа используйте почту аккаунта Supabase. Для других адресов настройте свой SMTP в Authentication → Emails; секреты SMTP и service-role ключ не размещайте на GitHub или в клиентском коде.

## Проверка

`node cloud-sync.test.cjs`

Тесты проверяют перенос локальных тайтлов, сохранение, конфликт ревизий, резервные копии, изменения во время отправки, разделение аккаунтов и восстановление очереди. Они используют тестовый сервер в памяти; отправка реальных писем проверяется пользователем при первом входе.
